# Key derivation, verification and recovery

This document answers "how does SoroWill derive my keys, and how do I recover
my account?" for issue #390.

## Short answer: SoroWill derives no keys

SoroWill is non-custodial. The web app **does not generate, derive, store or
see any private key, seed phrase or secret key** — for wallets, wills,
"vaults" or certificates. There is no key-derivation code in this repository.

| Component | What it actually does with keys |
| --- | --- |
| `src/lib/certificate.ts` | Builds a PDF snapshot of a will's **public, on-chain** terms (will id, owner address, status, balance, periods, beneficiary addresses) plus a QR code of the public verify URL. No keys, no hashing, no randomness, no signing. |
| `src/lib/freighter.ts` / `@sorowill/sdk` | Asks the Freighter browser extension for the connected account's **public key** (`G...` address) and asks Freighter to sign transactions. Signing happens inside Freighter; the app only receives the signed transaction. |
| Soroban contract | Identifies owners, guardians and beneficiaries by their Stellar addresses. Locked funds are held by the contract itself, not by an app-held "vault key". |

So the "certificate" is not a credential and cannot be used to move funds or
recover an account; it is a human-readable receipt that anyone can check
against the chain at the verify URL it embeds.

## Where your keys come from (wallet side)

Your key material lives entirely in your wallet (Freighter or another Stellar
wallet). Stellar wallets that use a recovery phrase, including Freighter,
follow [SEP-0005](https://github.com/stellar/stellar-protocol/blob/master/ecosystem/sep-0005.md):

- **Entropy / mnemonic:** BIP-39 recovery phrase generated by the wallet from
  the platform CSPRNG (12 or 24 words).
- **Seed:** BIP-39 PBKDF2-HMAC-SHA512 (2048 rounds) over the phrase and
  optional passphrase.
- **Algorithm:** SLIP-0010 hierarchical derivation for **Ed25519**
  (hardened-only).
- **Path:** `m/44'/148'/x'` — `44'` is BIP-44, `148'` is Stellar's SLIP-0044
  coin type, and `x'` is the account index (`0'` for the first account).
- **Output:** an Ed25519 keypair, shown as a `S...` secret seed and a `G...`
  public address (StrKey encoding).

These properties are the wallet's, not SoroWill's; consult your wallet's own
documentation and audits for its security review.

### Verifying your wallet's derivation

Use SEP-0005's published test vectors with any independent SEP-0005 tool
(offline, never with a real phrase). Test vector 1:

- Phrase: `illness spike retreat truth genius clock brain pass fit cave bargain toe`
- Path `m/44'/148'/0'` → `GDRXE2BQUC3AZNPVFSCEZ76NJ3WWL25FYFK6RGZGIEKWE4SOOHSUJUJ6`

If a tool reproduces the SEP-0005 vectors, the address it derives from *your*
phrase at `m/44'/148'/0'` should match the address SoroWill shows as the will
owner.

## Recovery

Because SoroWill holds no keys, recovery means recovering the **Stellar
account** that owns the will:

1. Install any SEP-0005 compatible Stellar wallet (e.g. Freighter on a new
   browser/device).
2. Choose "import / restore wallet" and enter your recovery phrase (or import
   the `S...` secret key directly).
3. Confirm the restored `G...` address matches the owner address on your will
   (it is printed on the certificate and on `/will/<id>`).
4. Connect the wallet to SoroWill; your wills are found by owner address and
   all actions (check-in, top-up, edit) work as before.

If you lose your recovery phrase **and** secret key, neither SoroWill nor
anyone else can recover the account. The will still executes according to its
on-chain terms (check-in deadline, grace period, guardians).

## What is and isn't implemented

- Implemented: public-key lookup and transaction signing delegated to
  Freighter; public-only certificate/QR generation.
- Not implemented: any in-app key generation, derivation, backup, export or
  social recovery. Adding any of these would require its own design and
  security review.
- `tests/unit/certificate.test.ts` asserts the certificate never contains
  Stellar secret-key material, so this invariant is regression-tested.
