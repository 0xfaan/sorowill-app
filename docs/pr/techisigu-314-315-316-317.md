# Toast roles, CountdownTimer semantics, CopyAddress timer cleanup, Accept-Language parsing

Each issue gets its core fix plus tests. Every new behavioural test fails on `main` and passes here. The remaining acceptance criteria are listed under "Not done in this PR".

## #314 - toast roles and live regions

**Done**
- `ToastItem` uses `role="alert"` for error toasts and `role="status"` for success/info, and no longer sets `aria-label={toast.variant}`, so the message text is what gets announced.
- `tests/unit/Toast.roles.test.tsx`: error -> `alert`, success/info -> `status`, no `aria-label` on either.
- `tests/unit/ShareVerification.test.tsx` looked for the clipboard-error toast by `role="status"`; updated to `alert` to match.

**Not done in this PR**
- Removing the container's own `aria-live="polite"` region (nested live regions).
- `aria-hidden` on the ✓ ✕ ℹ icon glyphs.

Note: samuelisi's PR #368 (#313) also edits `Toast.tsx` (`ToastItem`'s timer effect and dismiss button), on different lines; the second to merge may need a trivial rebase.

## #315 - CountdownTimer accessible name

**Done**
- The countdown `<span>` has `role="timer"` (no `aria-live`) and an `aria-label` such as "1 day 2 hours 3 minutes remaining" (minute precision, so it doesn't change every second), or "Overdue".
- `tests/unit/CountdownTimer.a11y.test.tsx`: `getByRole('timer', { name: ... })` for a future and an overdue deadline. Existing `CountdownTimer.test.tsx` (8 tests) unchanged and passing.

**Not done in this PR**
- The "Overdue —" prefix and the spoken label from next-intl messages (`en` + `es`).

## #316 - CopyAddress strings and reset timer

**Done**
- The 2s "Copied!" reset timer is stored in a ref, cleared before re-arming on each copy, and cleared on unmount.
- `tests/unit/CopyAddress.timer.test.tsx` (fake timers): unmount within 2s leaves no pending timer; a second copy at 1.5s restarts the 2s window (one timer, "Copied!" still shown at 2.5s, gone at 3.5s).

**Not done in this PR**
- Moving "Copied!", "Copy {address}" and "Copy to clipboard" into next-intl messages (`en` + `es`).
- Announcing "Copied!" once (it is currently in both the changing `aria-label` and the live span).

## #317 - Accept-Language negotiation

**Done**
- `getLocaleFromAcceptLanguage` and `supportedLocales` moved to `src/i18n/negotiate.ts` (exported); `request.ts` imports them, so the parser can be tested without `next/headers`.
- Malformed or out-of-range q-values (`q=abc`, `q=5`) are treated as 0 instead of `NaN`/raw, so the sort order is well defined; a missing q still defaults to 1.
- `tests/unit/negotiateLocale.test.ts`: `es-MX,es;q=0.9,en;q=0.8` -> es, `en`, empty/undefined, `fr` -> en, `fr;q=1,es;q=0.5` -> es, and malformed q-values ranked last (fails with the old parsing).

**Not done in this PR**
- Explicit `*` wildcard semantics (it currently just falls through to the `en` default) and tests for it.
