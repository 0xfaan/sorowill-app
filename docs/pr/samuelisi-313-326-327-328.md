# Toast timer reset, BeneficiaryForm row ids, stale resolution, address error a11y

Each issue gets its core fix plus a regression test. Every new behavioural test fails on `main` and passes here. The remaining acceptance criteria are listed under "Not done in this PR".

## #313 - toast auto-dismiss timer restarts when other toasts change

`ToastContainer` passed a new `() => removeToast(toast.id)` arrow on every render, and `ToastItem`'s timer effect depended on it.

**Done**
- `ToastItem` receives the provider's stable `removeToast` as `onDismiss(id)`; the effect depends on `[toast.id, onDismiss]`, so other toasts no longer restart it.
- `tests/unit/Toast.timer.test.tsx` (fake timers): add A, +3s, add B, +1.1s -> A is gone, B remains.

**Not done in this PR**
- Nothing further from the acceptance criteria; the issue is small enough that its core fix covers it.

## #326 - removed row's resolution state shows on another row

**Done**
- `removeRow` shifts the index -> id map past the removed row, so remaining rows keep their own ids, and drops the removed row's resolved address / resolution error.
- `tests/unit/BeneficiaryForm.rowIds.test.tsx`: resolve row 0, remove row 0 -> the former row 1 shows no resolved box.

**Not done in this PR**
- Removing the `setBeneficiaryIds` call inside `useMemo` (render-phase state update).
- Storing ids alongside the row data instead of an index-keyed map.

## #327 - resolution overwrites edits made while resolving

**Done**
- A `latestValue` ref (updated in an effect) holds the current rows; the resolved address is applied to it instead of the `value` captured when Resolve was clicked.
- `tests/unit/BeneficiaryForm.staleResolve.test.tsx`: start resolving row 0, change row 1's percentage, resolution completes -> row 0 has the resolved address and row 1 keeps 40.

**Not done in this PR**
- Handling a row removed or reordered while its address is resolving (the captured index can go stale).

## #328 - address errors not exposed to assistive tech

**Done**
- Address input sets `aria-invalid="true"` and `aria-describedby` pointing at the error when invalid; the error `<p>` has a stable id (`beneficiary-address-error-<index>`) and `role="alert"`, matching `GuardianForm`.
- `tests/unit/BeneficiaryForm.a11y.test.tsx`: invalid address -> `aria-invalid="true"` and `aria-describedby` = alert id; valid address -> neither attribute.

**Not done in this PR**
- Same treatment for the federated `resolutionError` message.
